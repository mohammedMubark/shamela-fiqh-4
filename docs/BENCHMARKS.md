# قياسات الأداء — shamela-fiqh-4

> **تنبيه أساسي:** كل الأرقام في هذا الملف قيست على **مجموعة اصطناعية** وُلِّدت بـ
> `scripts/make-fixtures.mjs`، لأن تنفيذ المشروع جرى في حاوية Linux سحابية لا يوجد فيها تثبيت
> شاملة حقيقي (انظر `FEASIBILITY.md` §0). **لم تُقس أي مكتبة شاملة حقيقية بعد.**
> القسم الأخير من هذا الملف مخصص لأرقامك أنت، وهو فارغ عمدًا حتى تشغّل القياس.

## ما الذي يُقاس أصلًا

لا تبني هذه الإضافة فهرسًا خاصًا بها: نصّ الكتب كله في فهارس Lucene التي كتبتها الشاملة نفسها
تحت `database/store`. فلا يوجد «زمن بناء فهرس» ولا «حجم فهرس مشتق» ليُقاسا — القياس كله على
زمن الاستجابة، وثبات الذاكرة، واكتمال النتائج.

**البنيوية** — ثبات الذاكرة والاكتمال — على حجم لا يمكن أن يكون قد «رُتِّب» له.
النطاق: المذاهب الأربعة.

| النمط | المواضع المطابقة | p50 | p95 |
| --- | ---: | ---: | ---: |
| `phrase` | 3,215 | **6.42 م.ث** | 14.96 م.ث |

### ثبات الذاكرة — القياس الحاسم

قيس بـ `--expose-gc` مع `global.gc()` قبل كل قراءة لـ RSS:

| الاستعلام | المواضع | الدفعات | مكتمل؟ | **نمو RSS** |
| --- | ---: | ---: | :---: | ---: |

| `any_terms` | **58,239** | 1,165 | ✅ 58,239/58,239 | **+20.8 م.ب** |

**نتائج أكثر بـ 20.5 مرة، ونموّ ذاكرة أقل.** لا علاقة بين حجم النتيجة والذاكرة المستهلكة:
الحلقة تحمل دفعة واحدة، لا مجموعة النتائج.

(الفارق بين 70,035 و58,239 هو أثر النطاق: الأول عدّ المطابقات في المجموعة كلها، والثاني

وهو الاستعمال المقصود منه.

## 3. كلفة استدعاء الأداة — أهم رقم في هذا الملف

الأرقام أعلاه تقيس المسار وقد فُتح المحرك سلفًا، فلا تُظهر ما يدفعه المستخدم فعلًا في كل نداء.
هذا القسم يقيس **استدعاء أداة كاملًا** عبر واجهة MCP الحقيقية. الفرق الوحيد بين الصفّين هو
`FIQH4_ENGINE_IDLE_MS`: القيمة 0 تعيد بالضبط السلوك القديم — إغلاق المساعد بعد كل نداء.

`fiqh4_search`، `limit=20`، `include_full_text=true`، p50 على 6 نداءات:

| | p50 | p95 |
| --- | ---: | ---: |
| عملية Java تُفتح وتُغلق في كل نداء (السلوك القديم) | **529.12 م.ث** | 535.62 م.ث |
| عملية Java دائمة (السلوك الحالي) | **19.91 م.ث** | 28.61 م.ث |
| | **أسرع 26.6 مرة** | |

ما كان يُدفع في كل نداء: إقلاع JVM، وفتح فهرس Lucene، وإعادة اكتشاف حقل الكتاب، ثم رمي
ذاكرة Lucene المؤقتة للاستعلامات والمرشِّحات كاملةً عند الإغلاق.

**على مكتبة حقيقية يكون الفرق أكبر لا أصغر:** فهرس المجموعة الاصطناعية 1,945 مستندًا، وفهرس
مكتبة حقيقية بالملايين — وكلفة فتحه هي ما أُلغي هنا، لا كلفة البحث فيه.

### عدد رحلات IPC لكل دفعة

قبل التغيير كان بناء كل موضع يطلب صفحته وحدها ثم عناوينها وحدها: دفعة من N موضعًا ≈ 2N رحلة
عبر الأنبوب. الآن تُعلَن الدفعة كاملة سلفًا فتُحلّ في **رحلة واحدة** لنصوص الصفحات وأخرى
للعناوين، مهما كبرت الدفعة. يثبّت هذا اختبار `tests/integration/engineLifecycle.test.ts`.

## 4. حجم الاستجابة وكلفتها بالتوكن

كانت كل «موضع» في الاستجابة يحمل نسخته من `query` و`match_mode` و`numbering_note`
(جملة عربية من ~70 حرفًا) و`content_trust`. وهي قيم لا تتغير بين مواضع الاستجابة الواحدة،
فصارت تُذكر مرة واحدة في `notes`.

| القياس (`fiqh4_search`، 20 موضعًا، بالنص الكامل) | القيمة |
| --- | ---: |
| حجم الاستجابة قبل | 32,399 بايت |
| حجم الاستجابة بعد | **26,359 بايت** |
| الموفَّر | **6,040 بايت — ‎−18.6%** |

النسبة **أعلى** في الاستعمال الافتراضي (`include_full_text=false`)، لأن الموضع حينها مقتطف
قصير فتصير الثوابت المحذوفة حصةً أكبر منه. ولا تُفقد أي معلومة: `notes.applies_to_ar` يذكر
صراحةً أن هذه القيم تسري على كل مواضع الاستجابة. أما صفوف التصدير في `results.jsonl` فتبقى
حاملةً لها، لأن الملف يُقرأ سطرًا سطرًا بعيدًا عن الغلاف ولا يكلّف توكنًا.

وكذلك `fiqh4_guide`: كان يقبل `topic` ثم يتجاهله ويعيد الدليل كاملًا في كل نداء؛ صار يعيد
القسم المطلوب وحده.

## 5. أرقام مكتبتك الحقيقية — لم تُقس بعد

هذا القسم فارغ عمدًا. لن يُملأ برقم لم يُقس.

```bash
# على الجهاز الذي فيه المكتبة
npm run build

# ويندوز
set FIQH4_SHAMELA_DIR=D:\shamela

npm run fiqh4:verify -- --out verify.json    # الفئات والتصنيف والتغطية
npm run fiqh4:bench                          # الأداء
npm run fiqh4:diagnose                       # عند وجود خلل
```

### ما يستحق الانتباه في نتائجك

- **الفارق في «استدعاء أداة»** هو أوضح ما ستراه: كلفة فتح فهرس بالملايين تُدفع مرة واحدة
  بدل كل نداء. إن لم تجد فرقًا فتحقق أن `FIQH4_ENGINE_IDLE_MS` ليس صفرًا.
- **`any_terms` بكلمات شائعة** هو أسوأ حالة: قد يطابق عشرات الآلاف من الصفحات.
  استعمل `phrase` أو `all_terms` للاستكشاف، وانتقل إلى `fiqh4_export_results` للاستقصاء.
- **الترحيل العميق المرتَّب بالصلة** يظل مكلفًا بنيويًا: بلوغ الموضع الخمسين ألفًا يعني
  اعتبار كل ما قبله. الترتيب بالصلة للصفحات الأولى، والتصدير للاستقصاء الكامل.
- إن كان **نمو الذاكرة يتناسب مع عدد النتائج** فذلك خلل يستحق الإبلاغ: المقصود ألا يتناسبا.
