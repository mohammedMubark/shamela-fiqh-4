# حل المشكلات — shamela-fiqh-4

**ابدأ دائمًا بـ `fiqh4_health`.** أكثر المشكلات شيوعًا يجيب عنها مباشرة، وحقل `warnings_ar`
فيه يذكر ما يحتاج انتباهك.

---

## المكتبة لا تُقرأ

### `SHAMELA_DIR_MISSING` — تعذر العثور على تثبيت المكتبة الشاملة

الأداة بحثت في مواضع مرشّحة ولم تجد `master.db`.

1. اضبط المسار صراحةً:
   ```
   FIQH4_SHAMELA_DIR=D:\shamela
   ```
2. المطلوب هو **مجلد الشاملة نفسه**، لا مجلد `database` ولا مجلد `Books`. والفيصل أن يحوي
   المجلد `database` و`app` **معًا**: الأول فيه `master.db` وفهارس `store`، والثاني فيه Java
   ومكتبات Lucene التي يقوم عليها البحث. مجلد `database` وحده لا يكفي.
3. تحقق يدويًا: `dir D:\shamela\database D:\shamela\app` (ويندوز) أو `ls` على لينكس/ماك.
4. في Claude Desktop اضبط «مجلد المكتبة الشاملة 4» في إعدادات الإضافة.

رسالة الخطأ تذكر كل المسارات التي جُرِّبت.

### `SCHEMA_UNRECOGNISED` — تعذّر التعرّف على البنية

نسخة الشاملة عندك تسمّي جداولها أو أعمدتها بأسماء لا يعرفها المرشّح.

شغّل `npm run fiqh4:verify` — يعرض الجداول والأعمدة التي عُثر عليها فعلًا. وتفاصيل الخطأ
تتضمن قائمة الجداول. **افتح مشكلة على المستودع مرفقًا بهذه القائمة** (وهي أسماء بنيوية فقط،
لا تحوي نصوص كتب) ليُضاف الاسم البديل إلى المرشّح.

### `BOOK_UNREADABLE`

ملف الكتاب موجود لكنه لا يُفتح: قد يكون تالفًا أو ناقص التنزيل أو مقفلًا ببرنامج آخر.
أغلق برنامج الشاملة وأعد المحاولة، ثم أعد تنزيل الكتاب من داخل الشاملة.

## البحث لا يجد شيئًا

### 1. هل فهرس الشاملة يُقرأ؟

لا تبني هذه الإضافة فهرسًا، بل تستعلم فهرس الشاملة تحت `database/store`. فالسؤال الأول ليس
«هل بُني الفهرس؟» بل «هل يُفتح؟». نادِ `fiqh4_health` وانظر:

| الحقل | ما يعنيه إن كان غير ذلك |
| --- | --- |
| `index.page_index` | `false` ⇒ لا يوجد `database/store/page` أصلًا: لم تُنزَّل كتب داخل الشاملة بعد |
| `index.readable` | `false` ⇒ الفهرس موجود لكنه لم يُفتح؛ السبب الحرفي في `index.error` و`index.java_stderr` |
| `index.page_documents` | صفر أو عدد أصغر بكثير من مكتبتك ⇒ الشاملة لم تكمل فهرستها بعد |

أو من الطرفية: `npm run fiqh4:diagnose`.

### 2. هل الكتب مُنزَّلة؟

الشاملة تُدرج في فهرسها كتبًا لم تُنزَّل بعد. هذه لا تُبحث ولا يمكن قراءتها.
`fiqh4_list_books` بـ `downloaded_only: true` يريك المتاح فعلًا، و`discover_issue` يعيدها في
`coverage.books_not_downloaded`.

### 3. هل النطاق أضيق مما تظن؟

إن مرّرت `madhhabs` فالكتب المصنَّفة `unclassified` **خارج النطاق**. وقد تكون مكتبتك تحوي كتبًا
مهمة لم تُصنَّف بعد:

```json
{ "madhhabs": ["shafii", "unclassified"] }
```

أو راجع التصنيف: `npm run fiqh4:verify`.

### 4. هل النمط صارم أكثر من اللازم؟

`phrase` يطلب الكلمات متتابعة بالترتيب. جرّب `all_terms` أولًا، ثم `any_terms`.

### 5. البحث حرفي لا دلالي

الأداة تطابق الكلمات، لا المعنى. المسألة قد ترد بلفظ آخر تمامًا. جرّب صياغات بديلة ومصطلحات
مرادفة. **هذا حدّ أصيل في الأداة**، مذكور في `fiqh4_guide`.

### 6. جرّب كلمة واحدة مميزة

إن نجحت كلمة واحدة وفشلت العبارة، فالمشكلة في الصياغة لا في الفهرس.

## مشكلات المؤشرات والنتائج

### `CURSOR_STALE`

**هذا سلوك مقصود، لا خلل.** يعني أن البيانات تغيّرت تحت المؤشر:

| السبب | ما تفعله |
| --- | --- |
| أُعيد بناء الفهرس | أعد البحث من البداية |
| تغيّر نص الاستعلام أو نمط المطابقة | المؤشر يخصّ استعلامًا واحدًا |
| تغيّر نطاق المذاهب أو الكتب | أبقِ النطاق ثابتًا أثناء الترحيل |
| تغيّر إصدار التطبيع (تحديث) | أعد بناء الفهرس |

البديل — المتابعة بصمت على بيانات مختلفة — يُسقط نتائج أو يكررها دون أن يعلم أحد.

### `CURSOR_INVALID`

المؤشر تالف أو ليس من هذه الأداة. أعد الطلب بدون `cursor`.

### النتائج تبدو ناقصة

انظر `truncation_reason`:

| القيمة | المعنى |
| --- | --- |
| `none` | لم يقع اقتطاع |
| `max_results_per_response` | امتلأت الدفعة — تابع بـ `next_cursor` |
| `byte_budget` | كبر حجم الاستجابة — قلّل `limit` أو `include_full_text: false` |
| `book_limit` | امتلأت دفعة سرد الكتب في `discover_issue` |

`total_hits` **دقيق دائمًا**. الفرق بينه وبين `returned` هو ما بقي.

### الترحيل بطيء جدًا على نتائج ضخمة

متوقع. الترتيب بالصلة يفرض على المحرك اعتبار كل المطابقات ليرتّبها، فيصير عميق الترحيل مكلفًا
(انظر `BENCHMARKS.md` §2).

**للاستقصاء الكامل استعمل `fiqh4_export_results`** — يمسح بترتيب المستند: 70,035 موضعًا في
7.6 ثانية مقابل دقائق بالترحيل.

## مشكلات التصنيف

### كتاب منسوب إلى المذهب الخطأ

1. تحقق من `classification_source` و`verification_status`. القيمة `unverified` تعني «من فئة
   الشاملة دون مراجعة بشرية».
2. صحّحه في `config/madhhab-overrides.json`:
   ```json
   { "overrides": [{ "book_id": "1234", "madhhab": "maliki", "reason": "راجعته بتاريخ ..." }] }
   ```
3. `fiqh4_health` بـ `refresh: true` — بلا إعادة تشغيل.

### كتب كثيرة `unclassified`

فئاتها غير مغطاة بالخريطة. `fiqh4_health` يعرض `unmapped_categories` مرتبةً بعدد الكتب.
أضف قواعد لها في `config/madhhab-map.seed.json`، أو ثبّت الكتب المهمة في التجاوزات.

### `OVERRIDES_INVALID`

ملف التجاوزات به مدخل غير صالح. كل مدخل يحتاج `book_id` نصيًا و`madhhab` من:
`hanafi` `maliki` `shafii` `hanbali` `comparative` `unclassified`. تفاصيل الخطأ تذكر العدد.

### `needs_review` كثيرة

طبيعي أول مرة. غالبًا سببها إشارة في العنوان تخالف الفئة — وهو بالضبط ما يستحق نظرك.
`fiqh4_list_books` بـ `verification_status: ["needs_review"]` يجمعها لك.

## التصدير

### `UNSAFE_OUTPUT_PATH` / `WRITE_INTO_SHAMELA_DIR`

المسار المطلوب خارج جذر الإخراج، أو داخل مجلد الشاملة. **الرفض مقصود.**
استعمل مسارًا نسبيًا يُحلّ داخل `FIQH4_OUTPUT_DIR`، أو غيّر `FIQH4_OUTPUT_DIR` نفسه.
الفحص يقارن بـ realpath، فالرابط الرمزي إلى مجلد الشاملة مرفوض أيضًا.

### `CHECKPOINT_MISMATCH`

`job_id` مستعمل من قبل لاستعلام أو فهرس مختلف. استعمل `job_id` جديدًا، أو احذف مجلد المهمة.
المزج بين نتيجتين في ملف واحد أسوأ من الرفض.

### التصدير انقطع

أعد الاستدعاء بنفس `job_id` ونفس الاستعلام. الكتب المكتملة لا يُعاد فحصها، والكتاب المنقطع
يُعاد من أوله. ويثبت اختبارُ الاستئناف تطابق الناتج مع تشغيل كامل نظيف.

### الملف ضخم جدًا

`include_full_text: false` يقلّصه كثيرًا: تبقى الإحالات والمقتطفات دون نص كل صفحة.

## Java / Lucene

نص كل صفحة يقيم في فهرس Lucene الذي تبنيه الشاملة، لذا **لا بحث بلا Java**: ليس ثمة محرك ثانٍ
يُرجَع إليه. وثلاث قطع يلزم توفرها، ولكلٍّ عطلها وعلاجها. `fiqh4_health` يذكر أيّها الناقص:

### `ENGINE_UNAVAILABLE` — «مساعد Lucene غير مبني»

أصناف الجسر غير موجودة في المسار الذي تذكره الرسالة. إن كنت تعمل من المصدر:

```bash
npm run build:java        # يحتاج JDK 21 وقت البناء فقط
```

وحزمة `.mcpb` الجاهزة تتضمن هذه الأصناف مترجَمة، فلا يقع هذا الخطأ معها.

### `ENGINE_UNAVAILABLE` — «تعذّر العثور على Java»

الشاملة تشحن نسختها تحت `app/<نظام>/<معمارية>/jre/2/bin`. فإن ظهر هذا الخطأ فالغالب أن
`FIQH4_SHAMELA_DIR` يشير إلى مجلد `database` وحده دون `app`. راجِع القسم الأول من هذا الملف.
ولمن ركّب الشاملة تركيبًا غير معتاد:

```bash
export FIQH4_JAVA_PATH=/absolute/path/to/java
```

### `ENGINE_UNAVAILABLE` — «تعذّر العثور على مكتبات Lucene»

`app/lucene/2/*.jar` مفقودة من تثبيتك. **هذه الإضافة لا تشحن Lucene** — تستعمل نسخة الشاملة
نفسها — فالعلاج إصلاح تثبيت الشاملة أو إعادته، لا تنزيل jar من عندك.

### `INDEX_MISSING` — تعذّر فتح `database/store/page`

الفهرس نفسه غير موجود أو غير مقروء. تأكد أن كتبك مُنزَّلة **داخل برنامج الشاملة**؛ الكتاب
المدرَج في الفهرس دون تنزيل لا نص له.

### البحث بطيء جدًا أو تنتهي مهلته

**أشيع سبب: الشاملة تعيد بناء فهارسها الآن.** أثناء ذلك تصير القراءة من `store` بطيئة جدًا،
ورسالة انتهاء المهلة تذكر هذا الاحتمال صراحةً. أغلق برنامج الشاملة، أو انتظر حتى يفرغ من
الفهرسة، ثم أعد المحاولة. والمهلة 180 ثانية لكل أمر.

### نتائج ترد بنصوص فارغة

المطابقات تُعثر عليها لكن `text_original` فارغ: يعني أن `body` في فهرس تثبيتك **مُفهرَس غير
مخزَّن**، فلا يمكن استرجاع النص منه وإن أمكن البحث فيه. تحقّق بـ:

```bash
npm run fiqh4:diagnose
```

وأرفق مخرجاته عند فتح المشكلة (بيانات بنيوية فقط، بلا نصوص كتب).

## التركيب والتشغيل

### الإضافة لا تظهر في Claude Desktop

1. `node -v` ≥ 22.5 — `node:sqlite` لا يوجد قبلها.
2. `npm run build` ثم تحقق من وجود `dist/index.js`.
3. `node scripts/smoke.mjs` — يشغّل الخادم المبني عبر stdio ويفحص الأدوات التسع.
4. راجع سجل Claude Desktop؛ الخادم يكتب على stderr.

### الخادم يبدأ ثم يتوقف

غالبًا مجلد شاملة غير صحيح. شغّل الخادم يدويًا لترى الخطأ:

```bash
FIQH4_SHAMELA_DIR=D:\shamela FIQH4_LOG_LEVEL=debug node dist/index.js
```

### مخرجات مشوّشة أو أخطاء بروتوكول

stdout محجوز لبروتوكول MCP. إن أضفت شيفرة تكتب على stdout فستُفسد الاتصال — **كل السجلات
تذهب إلى stderr**. اضبط `FIQH4_LOG_LEVEL=silent` للتقليل.

## تشخيص عام

```bash
node -v                                    # ≥ 22.5
npm run typecheck && npm test              # سلامة الشيفرة
npm run fixtures && npm run smoke          # على تركيبات اصطناعية
npm run fiqh4:verify                       # على مكتبتك الحقيقية
npm run checks                             # تطابق manifest، منع الشبكة، عدم شحن بيانات
```

عند فتح مشكلة، أرفق مخرجات `fiqh4_health` (بيانات بنيوية فقط، بلا نصوص كتب) ونسخة Node
والمنصة والرسالة الكاملة بـ `code`.
